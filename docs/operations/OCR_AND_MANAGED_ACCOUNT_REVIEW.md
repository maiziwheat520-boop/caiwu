# OCR 与受管账户复核操作

## 目标

离线识别账单截图，并在导入候选前拦截不完整字段；凡已提供过流水的个人或
公司账户都进入受管账户台账，受管账户之间的转账必须取得双边流水。

## OCR 预处理

1. 原始图片只放入一次性输入目录，不修改原件。
2. 在无网络、无数据库凭据的 `ocr-preprocessor` 容器中运行
   `scripts/preprocess_bill_images.py`。
3. 输出为私有 `ledgerbridge.bill-ocr.v1` JSON；终端只显示图片数、账单数、
   可复核数和摘要哈希，不显示账户或金额。
4. 只有账单号、周期、金额均存在且必要字段置信度不低于 85% 的账单可进入
   待复核候选。缺字段、低置信度或不支持版式必须留在预处理待办中。
5. 每个候选只绑定产生它的那一张原图。年度汇总等背景截图只留作上下文，
   不生成单笔账单。
6. 构建导入包时传入 `--ocr-observations <私有JSON>`；一旦提供该参数，旧的
   固定 Excel 单元格路径不再生成照片候选。

## 受管账户登记

- 用户提供过至少一份正式流水的账户自动登记为受管账户。
- 台账保存账户键、账户别名/尾号、归属人或归属公司，以及来源流水证据引用。
- 没有流水证据的账户不能仅凭交易备注自动登记。
- 个人账户和各家公司账户都进入同一个受管账户集合，但仍保留独立归属主体。

## 转账双边佐证

- 同一归属主体的两个受管账户互转：标记为“内部转账”。
- 不同公司或不同归属主体的受管账户互转：标记为“关联方转账”，不得当作
  同一主体内部划转直接抵消。
- 两种情况都要求另一账户出现同币种、反方向、等额、日期窗口内的流水。
- 只有单边流水时，候选状态为“需要另一账户流水”，不能确认成收入、支出或
  已完成内部转账。
- 双边匹配只提出配对建议，最终仍由人工确认；原始两侧流水永久保留。

## 失败处理

- OCR 依赖不可用、图片超限、符号链接、非图片文件：拒绝处理。
- 日期被截图裁切：标记周期缺失，不推算最后一位。
- 对方是受管账户但找不到另一侧流水：提示补充对应账户明细。
- 对方不是受管账户：按外部交易继续分类，不伪造内部配对。
