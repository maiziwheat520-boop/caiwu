# 原工资软件网页迁移矩阵

日期：2026-09-01

这次迁移以原工资表和辅助表为事实来源，网页按业务任务组织，不复刻 Excel 界面。所有新能力都限定在公司级 `TEST_ONLY` 工作区；付款、银行提交和可执行银行文件仍然关闭。

## 已迁移功能

| 原功能 | 网页结果 | 持久化与恢复 | 当前安全边界 |
| --- | --- | --- | --- |
| 填入工资主表 | 服务端重新解析已加密保存的 XLS/XLSX，合并有原因的人工调整并重算应发/实发 | 已完成；按公司、测试批次和账期保存，刷新可恢复 | 浏览器不能自行注入工资行；人工复核材料可编辑但不能生成代发草稿 |
| 生成正常代发表 | 从已保存主表中收集 `MYBANK` 渠道金额，生成版本化草稿 | 已完成；同一类型草稿按账期保存 | 草稿强制 `payable=false`、`submission_supported=false` |
| 生成补发代发表 | 只收集明确标记为 `SUPPLEMENT` 的正向调整 | 已完成 | 不猜测补发金额，不接受负数补发 |
| 更新工资汇总 | 保存人数、应发、实发及渠道汇总 | 已完成 | 汇总从当前保存主表重算，不接受浏览器提交汇总数 |
| 检查上月少发/多发 | 逐项选择并入本月、另行补发或忽略，并填写原因 | 已完成；原账期待办与本账期决定同时留痕 | 不允许把多发项变成补发；找不到员工时拒绝并入 |
| 核对本月已发 | 必须提供实际回单/流水证据编号，并逐人录入成功或失败及实际金额 | 已完成；生成差异和下一账期待办 | 不把草稿当回单，不会把“未提供”猜成“已支付” |
| 管理工资规则 | 编辑固定工资、津贴、渠道、发放类型、夜班标准、可休天数、工种和地点，保存后重算主表 | 已完成；规则独立版本化 | 工种、地点和渠道为空时不能保存；金额仅用整数分 |
| 检查规则与历史 | 检查来源异常、辅助材料缺失及相邻账期人员/金额变化 | 已完成；检查结果保存到对应账期 | 阻断项不会因查看或刷新自动消失 |

## 第一条可见闭环

`选择真实工资表 → 服务端解析 → 网页主表编辑/调整 → 重新计算 → 保存 → 刷新恢复`

这条闭环已由组件、BFF、Core 和 Payroll Provider 四层测试覆盖。命令使用乐观版本和幂等键，避免重复点击或并发覆盖。

## 真实数据就绪情况

已只读抽样一份 2026-07 实际工资表：61 行工资组成字段可解析，应发公式一致。该样本的发放渠道仍全部未分配，并存在身份字段缺失及实发差异阻断。因此它可以先进入网页主表供人工补全和复核，但在渠道、身份映射和差异解决前不能生成正常代发草稿。

## 暂不开放

- 可被银行直接导入的文件导出。
- 银行提交、发薪、付款或任何支付执行。
- 自动消解身份缺失、账户异常或实发差异。
- 未经实际回单支持的“已发”状态。

这些边界不是前端按钮隐藏，而是 Provider、Core、BFF 和接口契约四层共同拒绝。后续若要开放银行格式导出，应复用现有制表人、复核人、审批人分离及锁定版本门禁，而不是从网页工作台绕过。
