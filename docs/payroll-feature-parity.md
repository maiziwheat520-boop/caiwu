# 原工资软件网页迁移矩阵

日期：2026-09-01

这次迁移区分两个事实来源：历史对账金额以原 `酒店工资统计表.xlsx` 为权威口径；七、八月工资明细和辅助表继续保留为实验材料，只用于功能验证，不参与历史汇总金额。网页按业务任务组织，不复刻 Excel 界面。所有新能力都限定在公司级 `TEST_ONLY` 工作区；付款、银行提交和可执行银行文件仍然关闭。

## 历史对账展示

工资页顶部优先显示“各店工资与总汇总”。系统读取 `PAYROLL_SUMMARY` 总表，一次提供总表中的全部月份；用户通过账期选择器切换月份，页面展示各店当月工资和总计。如果材料库存在多个总表版本，页面分开列示版本，不跨版本合并；默认选择覆盖月份最多、最新账期最靠后的版本，用户仍可切换。

金额始终是整数分。总表有可读“总计”行时以该行为显示值，同时核对各店相加；两者不一致时保留显示总表总计并明确提示人工对账。总计缓存缺失时，才对同一总表内的门店行求和。员工姓名、账号、文件名、来源路径和原始字节不会进入该网页投影。

## 实验工作台闭环

`选择真实工资表 → 服务端解析 → 网页主表编辑/调整 → 重新计算 → 保存 → 刷新恢复`

这条闭环已由组件、BFF、Core 和 Payroll Provider 四层测试覆盖。命令使用乐观版本和幂等键，避免重复点击或并发覆盖。

发放验证中的“理论总额”直接取所选月份工资主表的全部员工实发工资合计，不只统计已生成代发草稿的员工。测试工作台录入三类账单实际金额后，页面同时展示 MYBANK、BOC、WECHAT 渠道小计、实际总额、理论总额和有符号差额；逐人一致且总额差额为零才显示核对一致。

## 真实数据就绪情况

已只读验证正式工资统计总表：覆盖 2023-07 至 2026-07 共 37 个月，2026-07 有 8 个门店，总计 369,787.18 元且与各店相加一致。另保留七、八月工资素材用于实验；已抽样的一份 2026-07 工资表有 61 行，渠道仍全部未分配，并存在身份字段缺失及实发差异阻断。因此实验素材不能替代历史总表，也不能在阻断解决前生成正常代发草稿。

## 暂不开放

- 可被银行直接导入的文件导出。
- 银行提交、发薪、付款或任何支付执行。
- 自动消解身份缺失、账户异常或实发差异。
- 未经实际回单支持的“已发”状态。

这些边界不是前端按钮隐藏，而是 Provider、Core、BFF 和接口契约四层共同拒绝。后续若要开放银行格式导出，应复用现有制表人、复核人、审批人分离及锁定版本门禁，而不是从网页工作台绕过。
